# API reference

> Generated by `npm run docs:generate` from the route registry — do not edit by hand. Interactive docs: `/api/docs` (when `SWAGGER_ENABLED=true`), machine-readable: `docs/openapi.json`.

Base path: `/api/v1`. Authenticated calls send `Authorization: Bearer <accessToken>`.

## Response envelope

```json
{ "success": true, "message": "…", "data": {}, "meta": null }
```

List endpoints return `data: []` and `meta: { page, pageSize, total, totalPages }`.

Errors:

```json
{ "success": false, "message": "Validation failed", "code": "VALIDATION_ERROR", "errors": [{ "field": "email", "message": "Please enter a valid email address" }], "requestId": "…" }
```

| Status | Meaning |
|---|---|
| 200 / 201 / 202 | Success / created / accepted |
| 400 | Validation failed (`errors[]` has field-level details) |
| 401 | Not authenticated, bad credentials or invalid token |
| 403 | Authenticated but role not permitted |
| 404 | Not found (also used for resources the caller may not know exist) |
| 409 | Conflict or invalid workflow transition (`INVALID_STATE_TRANSITION`) |
| 413 | Upload too large |
| 422 | Semantically invalid (business rule) |
| 429 | Rate limit exceeded |
| 500 / 503 | Server error / dependency or provider unavailable |

### `POST /api/v1/auth/login`

Step 1 of sign-in: email + password

When LOGIN_OTP_REQUIRED=true (default) no tokens are issued here: the response contains `challengeId` and an OTP is e-mailed. Complete sign-in with POST /auth/login/verify-otp. Wrong password, unknown email and locked account all return the same 401.

- **Access:** Public
- **Rate limit:** `login` (configurable in `.env`)
- **Success:** 200
- **Errors:** 400, 401, 403, 429, 500, 503

**Request body**

| Field | Type | Required | Validation |
|---|---|---|---|
| `email` | string | yes | max length 254 |
| `password` | string | yes | min length 1, max length 128 |
